# 상세 한글 Git 커밋 작성 규칙

사용자의 요청에 따라 커밋 제목·본문·변경 이력·설치 설명은 한글로 작성합니다.

## 형식

~~~text
[분류] 변경 목적을 한 줄로 설명

변경 목적:
- 왜 필요한 작업인지

주요 변경사항:
- 추가·수정된 파일과 동작

검증 결과:
- 실행한 테스트 명령과 결과
- 실제 운영 설치/재생 검증 여부 구분

영향 및 원복:
- FF·ALive·Shyni 및 기존 EPG에 미치는 영향
- 문제가 생겼을 때 되돌리는 방법
~~~

## 권장 분류

- [초기 구성]: 플러그인 등록 파일, 기본 폴더, 보안 제외 규칙
- [기능 추가]: EPG 수집·채널 매핑·XMLTV API
- [테스트]: 단위 테스트, 정합성 검증
- [문서]: README, 설치 방법, 변경 이력
- [버그 수정]: 오류 재현과 수정·회귀 테스트

## 규칙

- 기능을 한 번에 몰아넣지 말고 검증 가능한 단위로 나누어 커밋합니다.
- 커밋에는 반드시 변경 이유·확인 결과·운영 영향 범위를 기록합니다.
- 인증 키, OAuth 토큰, 실사용 전체 URL, 기기 접근 정보는 포함하지 않습니다.
- 외부 원본 epg/myepg는 직접 수정하지 않으며 Git 충돌을 만들지 않습니다.
- 배포 전 단계와 운영 적용 완료 상태를 문서에서 구분합니다.
